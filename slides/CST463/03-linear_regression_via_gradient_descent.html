Learning objectives

  • Reframe fitting a linear model as training: iteratively adapting parameters using a loss, not solving for them in one shot
  • Explain why we use an iterative approach here even though linear regression has a closed-form solution
  • Compare full-batch gradient descent, stochastic gradient descent, and mini-batch gradient descent, and describe the trade-offs between them
  • Connect linear classification’s loss to the same “loss + gradient” machinery as linear regression

The problem, again

What we already have

  • A dataset of examples: pairs (\mathbf{x}, y)
  • A model with parameters we can tune: \hat{y} = \mathbf{w} \cdot \mathbf{x} + b
  • A way to score any choice of (\mathbf{w}, b)
  • All three pieces came from last lecture

So what’s actually missing?

  • Last time, we picked (w, b) by hand, or let a random walk stumble into something decent
  • A real dataset can have thousands of points and dozens of features — eyeballing it, or getting lucky, doesn’t scale
    • As we add more dimensions we need more weights — w gets bigger, and a random step is decreasingly likely to land in a direction that actually helps
  • We need a systematic, automatic way to adapt (w, b) toward a lower loss

That process — adapting parameters using data and a loss — is what training a model means.

How do we quantify how well we’re doing?

Loss functions

  • We need a single number that says “how bad is this model, right now?”
  • That number is called a loss — smaller is better
  • For regression, we already have one: mean squared error L(w,b) = \frac{1}{N}\sum_{i=1}^N \big(\hat y_i - y_i\big)^2, \qquad \hat y_i = \mathbf{w} \cdot \mathbf{x_i} + b

Every method we build today — random search, gradient descent, SGD, mini-batch — is really just a different answer to: how do we use the loss to pick the next (w, b)?

Why not just solve it directly?

  • Linear regression actually has a closed-form solution — the normal equation: \mathbf{w}^\star = (\mathbf{X}^\top \mathbf{X})^{-1} \mathbf{X}^\top \mathbf{y}
  • So why not just… do that?

Note

This folds b into w by adding a column of 1s to X — a standard convention, but new notation if you haven’t seen it before.

  1. That matrix inverse gets expensive fast as the number of features grows
  2. It only exists because the model is linear — there’s no equivalent formula once the model isn’t
  3. Every model we build for the rest of this course — including ones with no closed form at all — gets fit the same iterative way
  4. Better to learn the general mechanism now, on a model simple enough to see clearly

Four ways to adapt (w, b)

We’ll watch the same dataset get fit four different ways:

  1. Random search — nudge and hope (already met this one)
  2. Gradient descent — use all the data to take one confident step
  3. Stochastic gradient descent — use just one point per step
  4. Mini-batch gradient descent — a tunable middle ground

from shiny import App, render, ui, reactive
import matplotlib.pyplot as plt
import numpy as np

rng = np.random.default_rng(7)

true_slope = 2.5
true_intercept = -15.0  # bigger than lecture 02's version so b's movement is visible, not just w's
error_sd = 9.0  # noisier than lecture 02's version

x = rng.uniform(0, 10, 40)
epsilon = rng.normal(0, error_sd, 40)
y_observed = true_slope * x + true_intercept + epsilon


def mse(w, b):
    y_pred = w * x + b
    return float(np.mean((y_observed - y_pred) ** 2))


STEP_SD_W = 0.4
STEP_SD_B = 1.5
TRAIL_LEN = 40

app_ui = ui.page_fluid(
    ui.layout_columns(
        ui.card(
            ui.card_header("choose_next_value(): random"),
            ui.input_action_button("step_once", "Random update", class_="btn-primary"),
            ui.input_action_button("step_ten", "Skip ahead 10x", class_="btn-secondary"),
            ui.input_action_button("reset", "Reset", class_="btn-outline-danger"),
            ui.hr(),
            ui.input_checkbox("greedy", "Only keep steps that improve", value=False),
            ui.hr(),
            ui.output_text_verbatim("state_text"),
        ),
        ui.card(
            ui.output_plot("walk_plot")
        ),
        col_widths=(4, 8),
    )
)


POINTS_PER_STEP = len(x)  # a "better or worse" call touches all 40 points


def server(input, output, session):
    state = reactive.Value({"w": 0.0, "b": 0.0, "mse": mse(0.0, 0.0), "step": 0, "points_seen": 0})
    history = reactive.Value([])

    def do_step():
        s = state.get()
        w_new = s["w"] + rng.normal(0, STEP_SD_W)
        b_new = s["b"] + rng.normal(0, STEP_SD_B)
        mse_new = mse(w_new, b_new)
        improved = mse_new < s["mse"]
        step = s["step"] + 1
        points_seen = s["points_seen"] + POINTS_PER_STEP

        hist = history.get() + [
            {"w": w_new, "b": b_new, "mse": mse_new, "improved": improved, "step": step}
        ]
        history.set(hist[-TRAIL_LEN:])

        if improved or not input.greedy():
            state.set({"w": w_new, "b": b_new, "mse": mse_new, "step": step, "points_seen": points_seen})
        else:
            state.set({**s, "step": step, "points_seen": points_seen})

    @reactive.effect
    @reactive.event(input.step_once)
    def _():
        do_step()

    @reactive.effect
    @reactive.event(input.step_ten)
    def _():
        for _ in range(10):
            do_step()

    @reactive.effect
    @reactive.event(input.reset)
    def _():
        history.set([])
        state.set({"w": 0.0, "b": 0.0, "mse": mse(0.0, 0.0), "step": 0, "points_seen": 0})

    @output
    @render.text
    def state_text():
        s = state.get()
        return (
            f"Step {s['step']}  |  points touched so far: {s['points_seen']}\n\n"
            f"w = {s['w']:.2f}, b = {s['b']:.2f}  |  MSE = {s['mse']:.1f}"
        )

    @output
    @render.plot
    def walk_plot():
        s = state.get()
        hist = history.get()

        fig, ax = plt.subplots(figsize=(8, 5))

        ax.scatter(
            x, y_observed, s=45, alpha=0.7, color="steelblue", zorder=3,
            label="Observed data"
        )

        x_line = np.linspace(0, 10, 200)

        n = len(hist)
        for i, h in enumerate(hist):
            age = n - i
            alpha = max(0.05, 1 - (age - 1) / TRAIL_LEN)
            color = "tab:blue" if h["improved"] else "tab:red"
            y_line = h["w"] * x_line + h["b"]
            ax.plot(x_line, y_line, color=color, alpha=alpha * 0.8, linewidth=1.5)

        y_current = s["w"] * x_line + s["b"]
        ax.plot(
            x_line, y_current, color="black", linewidth=3,
            label=f"Current (step {s['step']})"
        )

        ax.set_xlim(0, 10)
        ax.set_ylim(float(y_observed.min()) - 10, float(y_observed.max()) + 10)
        ax.set_xlabel("x")
        ax.set_ylabel("y")
        ax.legend(loc="upper left")
        ax.set_title(
            f"Step {s['step']}  |  {s['points_seen']} point-evaluations so far\n"
            "Blue = improved, red = made it worse"
        )

        return fig


app = App(app_ui, server)

Gradient Descent

Train using all the data

The idea, before the math

Each step, decrease the “badness” of the model as fast as possible

  • “Badness” is just our loss — so the goal is to minimize the loss
  • Random search nudged (w, b) and hoped that helped
  • Gradient descent instead asks: of every direction we could move (w, b), which one decreases the loss fastest right now — and moves exactly that way

The loss, written out

  • Same MSE loss as before, now written as a function of the whole dataset: L(w,b) = \frac{1}{N}\sum_{i=1}^N \big(\hat y_i - y_i\big)^2, \qquad \hat y_i = w x_i + b
x_i, y_i one training example constant — fixed by the dataset
N number of training examples constant
w, b model parameters trainable — what we’re actually adjusting
\hat y_i prediction derived — changes whenever w, b do
L the loss derived — the number we’re trying to shrink

Given this measure of how bad we are, what do we do?

The gradient of the loss

  • Take the partial derivative of L with respect to each trainable parameter (w and b): \frac{\partial L}{\partial w} = \frac{2}{N}\sum_{i=1}^N (\hat y_i - y_i)\,x_i \qquad\qquad \frac{\partial L}{\partial b} = \frac{2}{N}\sum_{i=1}^N (\hat y_i - y_i)
  • Stack them into a gradient vector, same idea as \nabla f from last lecture: \nabla L = \left[\frac{\partial L}{\partial w}, \frac{\partial L}{\partial b}\right]
  • This points toward steepest loss — so we step in the opposite direction

The gradient descent algorithm

  1. Compute the prediction \hat y_i for every one of the N points, using the current (w, b)
  2. Compute the gradient \nabla L from those predictions — average the per-point contributions
  3. Update: w \leftarrow w - \eta \dfrac{\partial L}{\partial w}, and b \leftarrow b - \eta \dfrac{\partial L}{\partial b}
  4. Repeat until the loss stops improving (or some other criteria – future work)


η (“eta”) is the learning rate — how big a step to take in the gradient’s direction

Aside: What could go wrong with η?

  • Too small, and training crawls — technically correct, painfully slow
  • Too large, and a step can overshoot the bottom of the bowl entirely, making the loss worse — try pushing it too far in the widget below and see for yourself
  • Choosing η well is its own skill; we’ll come back to it later in the course

from shiny import App, render, ui, reactive
import matplotlib.pyplot as plt
import numpy as np

rng = np.random.default_rng(7)

true_slope = 2.5
true_intercept = -15.0  # bigger than lecture 02's version so b's movement is visible, not just w's
error_sd = 9.0

x = rng.uniform(0, 10, 40)
epsilon = rng.normal(0, error_sd, 40)
y_observed = true_slope * x + true_intercept + epsilon


def mse(w, b):
    y_pred = w * x + b
    return float(np.mean((y_observed - y_pred) ** 2))


def gradient(w, b):
    y_pred = w * x + b
    error = y_pred - y_observed
    dw = 2 * np.mean(error * x)
    db = 2 * np.mean(error)
    return dw, db

DIVERGED_LIMIT = 1e4
POINTS_PER_STEP = len(x)  # every gradient uses all 40 points

def server(input, output, session):
    state = reactive.Value({"w": 0.0, "b": 0.0, "mse": mse(0.0, 0.0), "step": 0, "diverged": False, "points_seen": 0})
    history = reactive.Value([])

    def do_step():
        s = state.get()
        if s["diverged"]:
            return

        dw, db = gradient(s["w"], s["b"])
        lr = input.lr()
        w_new = s["w"] - lr * dw
        b_new = s["b"] - lr * db
        step = s["step"] + 1
        points_seen = s["points_seen"] + POINTS_PER_STEP

        if not (np.isfinite(w_new) and np.isfinite(b_new)) or abs(w_new) > DIVERGED_LIMIT or abs(b_new) > DIVERGED_LIMIT:
            state.set({**s, "step": step, "diverged": True, "points_seen": points_seen})
            return

        mse_new = mse(w_new, b_new)
        improved = mse_new < s["mse"]

        hist = history.get() + [

            ax.plot(x_line, y_line, color=color, alpha=alpha * 0.8, linewidth=1.5)

        if not s["diverged"]:

That’s a very different walk

  • Every early step moves confidently downhill — no wasted red steps, unlike random search
  • …unless η was too large, in which case every step turns red and the loss explodes — that’s η doing exactly what we warned about

Caution

The catch: every single step required looking at all 40 points. Scale that up to a real dataset, and each step gets expensive fast

Stochastic Gradient Descent

Train using one point at a time

So do we need to evaluate on everything?

  • Every gradient descent step needs the error from all 40 points, every time
  • What if we didn’t? What if we picked one point and stepped using just its gradient?
    • We’ll eventually see all the data anyway, right?
  • That’s the idea behind stochastic gradient descent (SGD) — “stochastic” because which point we grab is random

Why would this be good?

  • Each step is now cheap and constant-time — it doesn’t matter whether the dataset has 40 rows or 40 billion
  • We can take far more steps for the same amount of computation
  • We never need the whole dataset in memory at once — it can even arrive one example at a time, as a stream

The Catch

  • One point’s gradient is not the loss’s true gradient — it’s a cheap, noisy estimate of it
  • A single unusual point can point the update in a bad direction entirely
  • Expect the path to visibly bounce, not glide smoothly downhill the way full-batch gradient descent did

The SGD update

  • The full-batch gradient averaged the per-point contributions: \frac{\partial L}{\partial w} = \frac{2}{N}\sum_{i=1}^N (\hat y_i - y_i)\,x_i
  • SGD just uses one term of that sum — no averaging, no waiting on the rest of the data: \frac{\partial L_i}{\partial w} = 2(\hat y_i - y_i)\,x_i, \qquad \frac{\partial L_i}{\partial b} = 2(\hat y_i - y_i)
  • Same formula, same update rule — just computed from one example instead of all of them

The stochastic gradient descent algorithm

  1. Pick one training example (x_i, y_i) at random
  2. Compute the gradient of the loss using just that point
  3. Update (w, b) the same way as before: step opposite the gradient, scaled by η
  4. Repeat — a different random point every time

That’s a different kind of walk entirely

  • No two steps move the same way — direction depends entirely on which point got picked
  • It’s noisy, but it isn’t going nowhere — over enough steps, it still drifts toward the loss’s minimum, on average


Tip

The catch: we traded “confident but expensive” for “cheap but jumpy”.

What’s the middle ground?

Mini-batch Gradient Descent

Train using a handful of points at a time

The idea

  • SGD went too far one way — one point is barely a hint of the true gradient
  • Full gradient descent went too far the other way — every step costs the whole dataset
  • Mini-batch gradient descent: average the gradient over a small, randomly-sampled batch of k points — pick anywhere on the dial between the two

The mini-batch update

  • Same gradient formula as full-batch, just averaged over k points instead of all N: \frac{\partial L}{\partial w} \approx \frac{2}{k}\sum_{i \,\in\, \text{batch}} (\hat y_i - y_i)\,x_i \qquad\qquad \frac{\partial L}{\partial b} \approx \frac{2}{k}\sum_{i \,\in\, \text{batch}} (\hat y_i - y_i)


Important

SGD and Gradient Descent are special cases of mini-batch Gradient Descent

  • k = 1 is SGD
  • k = N is full-batch gradient descent

The mini-batch gradient descent algorithm

  1. Sample a random batch of k points (without replacement) from the dataset
  2. Compute the gradient of the loss using just that batch
  3. Update (w, b) the same way as before: step opposite the gradient, scaled by η
  4. Repeat — a different random batch every time

Mini-batch, live

  • Same 40 points, same noise as every widget today — now you pick the batch size k yourself
  • The k sampled points light up in orange each step — watch the walk get smoother as k grows

from shiny import App, render, ui, reactive
import matplotlib.pyplot as plt
import numpy as np

rng = np.random.default_rng(7)

true_slope = 2.5
true_intercept = -15.0
error_sd = 9.0

x = rng.uniform(0, 10, 40)
epsilon = rng.normal(0, error_sd, 40)
y_observed = true_slope * x + true_intercept + epsilon
N = len(x)

step_rng = np.random.default_rng(11)  # separate stream: which batch gets sampled each step


def mse(w, b):
    y_pred = w * x + b
    return float(np.mean((y_observed - y_pred) ** 2))


TRAIL_LEN = 40
DIVERGED_LIMIT = 1e4

app_ui = ui.page_fluid(
    ui.layout_columns(
        ui.card(
            ui.card_header("Mini-batch: k random points per step"),
            ui.input_slider("batch_size", "Batch size (k)", min=1, max=40, value=8, step=1),
            ui.input_slider("lr", "Learning rate (η)", min=0.001, max=0.02, value=0.01, step=0.001),
            ui.input_action_button("step_once", "Take a mini-batch step", class_="btn-primary"),
            ui.input_action_button("step_ten", "Skip ahead 10x", class_="btn-secondary"),
            ui.input_action_button("reset", "Reset", class_="btn-outline-danger"),
            ui.hr(),
            ui.output_text_verbatim("state_text"),
        ),
        ui.card(
            ui.output_plot("walk_plot")
        ),
        col_widths=(4, 8),
    )
)


def server(input, output, session):
    state = reactive.Value({"w": 0.0, "b": 0.0, "mse": mse(0.0, 0.0), "step": 0, "diverged": False, "idx": None, "points_seen": 0})
    history = reactive.Value([])

    def do_step():
        s = state.get()
        if s["diverged"]:
            return

        k = input.batch_size()
        idx = step_rng.choice(N, size=k, replace=False)
        xb, yb = x[idx], y_observed[idx]
        pred_b = s["w"] * xb + s["b"]
        error_b = pred_b - yb
        dw = 2 * np.mean(error_b * xb)
        db = 2 * np.mean(error_b)

        lr = input.lr()
        w_new = s["w"] - lr * dw
        b_new = s["b"] - lr * db
        step = s["step"] + 1
        points_seen = s["points_seen"] + k

        if not (np.isfinite(w_new) and np.isfinite(b_new)) or abs(w_new) > DIVERGED_LIMIT or abs(b_new) > DIVERGED_LIMIT:
            state.set({**s, "step": step, "diverged": True, "idx": idx, "points_seen": points_seen})
            return

        mse_new = mse(w_new, b_new)
        improved = mse_new < s["mse"]

        hist = history.get() + [
            {"w": w_new, "b": b_new, "mse": mse_new, "improved": improved, "step": step}
        ]
        history.set(hist[-TRAIL_LEN:])

        state.set({"w": w_new, "b": b_new, "mse": mse_new, "step": step, "diverged": False, "idx": idx, "points_seen": points_seen})

    @reactive.effect
    @reactive.event(input.step_once)
    def _():
        do_step()

    @reactive.effect
    @reactive.event(input.step_ten)
    def _():
        for _ in range(10):
            do_step()

    @reactive.effect
    @reactive.event(input.reset)
    def _():
        history.set([])
        state.set({"w": 0.0, "b": 0.0, "mse": mse(0.0, 0.0), "step": 0, "diverged": False, "idx": None, "points_seen": 0})

    @output
    @render.text
    def state_text():
        s = state.get()
        if s["diverged"]:
            return f"Step {s['step']}  |  points touched so far: {s['points_seen']}  |  Diverged! η is too large — hit Reset and try a smaller value."
        return (
            f"Step {s['step']}  |  points touched so far: {s['points_seen']}\n"
            f"w = {s['w']:.2f}, b = {s['b']:.2f}  |  MSE = {s['mse']:.1f}"
        )

    @output
    @render.plot
    def walk_plot():
        s = state.get()
        hist = history.get()

        fig, ax = plt.subplots(figsize=(8, 5))

        ax.scatter(
            x, y_observed, s=45, alpha=0.7, color="steelblue", zorder=3,
            label="Observed data"
        )

        x_line = np.linspace(0, 10, 200)

        n = len(hist)
        for i, h in enumerate(hist):
            age = n - i
            alpha = max(0.05, 1 - (age - 1) / TRAIL_LEN)
            color = "tab:blue" if h["improved"] else "tab:red"
            y_line = h["w"] * x_line + h["b"]
            ax.plot(x_line, y_line, color=color, alpha=alpha * 0.8, linewidth=1.5)

        if not s["diverged"]:
            y_current = s["w"] * x_line + s["b"]

            if s["idx"] is not None:
                idx = s["idx"]
                xb, yb = x[idx], y_observed[idx]
                pred_b = s["w"] * xb + s["b"]
                ax.vlines(
                    xb, np.minimum(yb, pred_b), np.maximum(yb, pred_b),
                    color="darkorange", alpha=0.7, linewidth=2, zorder=4,
                    label="Batch used this step"
                )
                ax.scatter(
                    xb, yb, s=110, facecolors="none", edgecolors="darkorange",
                    linewidths=2, zorder=5
                )

            ax.plot(
                x_line, y_current, color="black", linewidth=3,
                label=f"Current (step {s['step']})"
            )

        ax.set_xlim(0, 10)
        ax.set_ylim(float(y_observed.min()) - 10, float(y_observed.max()) + 10)
        ax.set_xlabel("x")
        ax.set_ylabel("y")
        ax.legend(loc="upper left")
        ax.set_title(
            f"Step {s['step']}  |  {s['points_seen']} point-evaluations so far\n"
            "Blue = improved, red = made it worse"
        )

        return fig


app = App(app_ui, server)

What did we learn by turning the dial?

  • Small k: cheap steps, lots of them, but a bouncy path — SGD’s territory
  • Large k: confident steps, but each one costs more — gradient descent’s territory


  • In practice, k gets chosen to balance noise against how much data fits comfortably in memory at once — commonly powers of 2, like 32, 64, 128
  • This dial is what real training loops actually use — “SGD” in PyTorch almost always means mini-batch SGD under the hood

Comparing the four

Same computation budget, four different walks

  • All four methods below get the exact same computation budget: 2,000 point-evaluations
    • They all still have the 40 point dataset so this is 50 epochs
      • An epoch is one full pass through the dataset
  • Notice the difference in how the evaluation budget gets spent

What the plot is telling us

  • Gradient descent (black) descends smoothly and predictably — but for this budget, it only gets 50 steps (50 epochs, one step per epoch)
  • SGD (red) gets 2,000 steps for the same budget — noisy, but it’s still the fastest to a low loss here
  • Mini-batch (blue) splits the difference — smoother than SGD, far more steps than GD
  • Random search (gray) never gets a sense of direction — with nothing pulling it back, the loss can end up anywhere, and typically drifts worse over time

Note

The dashed green line is the least-squares solution on this exact noisy sample — computed with the normal equation from a few slides back, not the “true” (w, b) we generated the data from. Because of the noise, those aren’t the same thing, and least squares always wins on its own sample.

Comparing Mini-batch Sizes

Let’s vary minibatch size with 40 datapoints and a budget of 4000 evaluations

What turning the dial actually buys you

  • Small k (light blue) is noisiest, but its many cheap steps still get it to a low loss fastest, early on
  • Large k (dark blue) is the smoothest, but under a fixed budget it gets far fewer steps — and visibly lags behind here
  • There’s no universally “best” k — it’s a real trade-off, tuned per problem, per budget, per hardware

The takeaway

More steps with a noisy gradient often beats fewer steps with an exact one

  • This is why SGD and mini-batch dominate in practice, especially on huge datasets — a single full-batch gradient descent step on a billion-row dataset costs a billion point-evaluations before (w, b) has moved even once
  • Gradient descent isn’t wrong — it’s just not what anyone actually runs at scale
  • For some concrete numbers on “huge dataset”:
    • ImageNet is ~138GB
    • The Reddit dataset (used for graph learning benchmarks) is ~2.841TB
